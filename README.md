# ATLAS UI Kit — Help Desk

Готовая практическая работа № 5 по дизайн-токенам. Семантическая HTML-страница, три уровня CSS-токенов, светлая/тёмная/системная темы и обычная/компактная плотность. Использованы HTML, CSS Custom Properties и Vanilla JavaScript; сторонних UI-библиотек нет.

- Репозиторий: [mucurgng/atlas-ui-kit](https://github.com/mucurgng/atlas-ui-kit)
- Рабочая страница: [UI Kit](https://mucurgng.github.io/atlas-ui-kit/)
- Краткий отчёт: [REPORT.md](REPORT.md)
- Четыре скриншота: [screenshots](screenshots/)

## Исходная проблема и выполненная работа

В стартовом проекте были незавершённые стили кнопок, полей и уведомлений, отсутствовали тёмная тема и сохранение пользовательских настроек. Работа выполнена последовательно: централизованы токены, реализованы темы, состояния компонентов, плотность и warning, затем проверены адаптивность, контраст и поведение переключателей. Разметка и доступные подписи стартового проекта сохранены и дополнены.

## Запуск

Из каталога с `index.html` выполните:

```sh
python -m http.server 5500
```

Откройте [localhost:5500](http://localhost:5500). Сборка и установка пакетов не требуются. Можно также открыть `index.html` напрямую; для предсказуемой работы хранилища рекомендуется HTTP-сервер.

## Архитектура токенов

В `tokens.css` объявлены **105 уникальных токенов**. Цветовые значения находятся только в этом файле; в `components.css` нет HEX/RGB-значений.

| Уровень | Назначение | Пример |
| --- | --- | --- |
| Primitive | Значение без привязки к компоненту | `--base-blue-700: #1853a4` |
| Semantic | Роль в интерфейсе | `--color-primary: var(--base-blue-700)` |
| Component | Применение роли в компоненте | `--button-bg-primary: var(--color-primary)` |

Реальные цепочки до CSS-селектора:

1. `--base-blue-700 → --color-primary → --button-bg-primary → .button--primary` — фон основной кнопки в светлой теме.
2. `--base-slate-400 → --color-border-control → --control-border → .input, .select` — граница полей в светлой теме.
3. `--base-sky-800 → --color-info → --alert-color-info → .alert--info` — текст информационного сообщения.
4. `--base-amber-800 → --color-warning → --alert-color-warning → .alert--warning` — текст предупреждения.

В тёмной теме меняются семантические роли: например, `--color-primary` ссылается на `--base-blue-300`, а `--color-on-primary` — на `--base-night-950`. Компонентные селекторы остаются общими.

Другие группы: размеры текста 12/14/16/20/24 px и адаптивный display, насыщенность и межстрочный интервал, отступы 4/8/12/16/20/24/32/48 px, три радиуса и тень поверхности.

## Компоненты и поведение

| Компонент | Варианты и состояния |
| --- | --- |
| Button | Primary, secondary, ghost; default, hover, active, focus-visible, disabled |
| Input / select | Общая высота, placeholder, hover, focus-visible, disabled; invalid у поля email |
| Alert | Info, success, error, warning; смысл передаётся текстом и символом |
| Карточки и образцы | Поверхности, типографика, шкала отступов и цветовые роли |

Первая кнопка выводит демонстрационный результат в `role="status"`. Это библиотека компонентов: реальная отправка заявок и серверная обработка не входят в проект. Поле email намеренно показывает пример ошибки.

## Темы и плотность

- `auto`: атрибут `data-theme` отсутствует; CSS применяет системное предпочтение.
- `light` / `dark`: атрибут устанавливает ручную тему, которая имеет приоритет над ОС.
- `color-scheme` согласован с темой для встроенных элементов браузера.
- Ключ `atlas-theme` хранит тему, `atlas-density` — плотность; неправильные значения заменяются на auto/normal.
- При запрете localStorage интерфейс продолжает работать, но настройка не сохраняется между загрузками.
- Настройки применяются до подключения CSS; изменения хранилища синхронизируются между вкладками.

Компактная плотность задаётся на `:root[data-density="compact"]`:

| Компонентный токен | Обычная | Компактная |
| --- | --- | --- |
| `--button-height` | 44 px | 36 px |
| `--control-height` | 44 px | 36 px |
| `--button-padding-inline` | 20 px | 12 px |
| `--control-padding-inline` | 16 px | 12 px |
| `--component-gap` | 12 px | 8 px |
| `--alert-padding` | 16 px | 12 px |

## Ответы на вопросы

**Почему плотность задаётся компонентными токенами?** Плотность меняет геометрию, а не смысл цветов или структуру HTML. Переопределение шести токенов одновременно меняет высоты, внутренние отступы и интервалы у всех компонентов без дублирования CSS. Цветовая тема при этом остаётся независимой.

**Почему тёмная тема не должна хранить прямые цвета внутри `.button`?** Прямые значения связывают кнопку с конкретной палитрой и заставляют повторять правила для каждой темы. Семантическая роль меняется централизованно, поэтому одинаковое правило кнопки работает в обеих темах и сохраняет общую архитектуру.

Для подключения ко второй странице достаточно импортировать сначала `tokens.css`, затем `components.css`, использовать классы компонентов и при необходимости подключить логику настроек. Текущий `theme.js` связан с демонстрационной страницей; на другой странице обработчики демонстрационных кнопок следует убрать или адаптировать.
